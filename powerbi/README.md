# Phisheries Power BI report

This folder contains a Power BI project, its editable PBIR report definition,
an import semantic model and the equivalent Power Query scripts. It uses the
results generated by `Department_Of_Phisheries.ipynb`.

## Open and refresh

1. Run the notebook from top to bottom if `outputs/powerbi/` is missing or you
   have changed the data or analysis.
2. Open `Phisheries.pbip` in a compatible Power BI Desktop installation. You can
   also open `Phisheries.Report/definition.pbir` directly. Depending on Desktop's
   version, its project/PBIR options may need enabling under Options.
3. Under **Transform data → Edit parameters**, check `DataFolder`. Its initial
   value is `D:\FODS PROJECT\outputs\powerbi`. Keep `UseBackend = false` for
   local files.
4. Refresh the model. If prompted, configure the local file-source credentials
   and appropriate privacy settings. No account, Fabric workspace or publishing
   step is required for the local report.
5. Inspect all four pages and save from Desktop. Use Desktop's **Save as** if a
   PBIX is required for submission.

If a Desktop version cannot open the project format, the CSVs and `PowerQuery.m`
provide a fallback: create `DataFolder` (Text) and `UseBackend` (True/False)
parameters, then paste each named query separately into a blank query's Advanced
Editor. That fallback imports the data but requires rebuilding the visuals in
that Desktop version; it does not automatically create the supplied report pages.

## Pages and interpretation

| Page | Content | Sample |
|---|---|---|
| Dataset overview | Class counts, URL-length groups, TLD rates and quality audit | Unique URLs for counts; one URL per host for TLDs |
| Review indicators | Feature-presence rates, review notes and Rule A/B trade-offs | Consistently labeled, one-per-host sample |
| Statistical evidence | Course test statistics, raw p-values, differences and decisions at 0.05 | As named in each evidence row |
| Supporting model | Majority baseline, logistic regression, predictions and partitions | Internal host-grouped model test partition |

The feature slicer filters the feature-presence chart. Evidence-page slicers
filter the saved evidence table. Aggregate tables are intentionally independent:
a feature filter does not silently change the separately calculated rule tests.
Do not create joins that multiply aggregate counts. The page notes describe the
sample and inference limits.

P-values are precomputed in the notebook. They do not become new tests when a
report viewer filters a visual. The 15 questions use the Welch two-sample
t-test, chi-square independence, paired t-test and permutation test taught in
the supplied slides. Decisions use raw p-values at 0.05. Multiple exploratory
comparisons increase false-positive risk. `EstimateUnits` describes each
difference or summary. Very small floating-point p-values use the display text
`below numerical precision`, rather than a literal probability of zero.

## Backend connection for the bonus demonstration

From the project root, start:

```powershell
python backend/server.py
```

In Power BI, set `UseBackend = true` and Refresh. The partitions request
`http://127.0.0.1:8765/data/<table>.csv` instead of opening the local files. Use
Anonymous credentials for this local web source. Both modes read the same saved
analysis, so their imported values should agree. The server must remain running
while Power BI refreshes. To switch back, set `UseBackend = false`.

Useful endpoints:

- `/health`: readiness and the whitelist of exported tables.
- `/api/summary`: dataset fingerprint, sample counts and calculated run results.
- `/api/evidence`: the statistical evidence as JSON.
- `/data/feature_rates.csv`: within-class feature counts and rates.
- `/data/statistical_evidence.csv`: the complete test evidence.

The backend serves files from the last completed notebook run; it does not
perform URL detection or rerun tests on request. This is an HTTP import/refresh
connection, not DirectQuery or streaming. Publishing would require hosting or a
gateway configured separately; localhost is for the local demonstration.

## Validation status

The PBIP, PBISM, PBIR, page and visual JSON definitions were validated against
the published Microsoft schemas. Referenced fields/measures were checked against
the semantic model; each visual container fits within its report page. The
backend endpoints were exercised against the saved exports.

Power BI Desktop is not available in the standard installation paths in this
environment. The report has not been rendered or refreshed in Desktop, so final
engine compatibility, source credential prompts and visual appearance need to
be checked there. JSON schema validation alone does not establish those results.
